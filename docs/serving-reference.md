# 사용량 기준과 공공 데이터

확인일: 2026-11-02(한국 시간). 사용자 요청에 따라 일반 음료 250mL 보정과 식품별 공공 기준을 함께 검토했다. **이번 코드의 250mL는 사용자가 승인한 앱 기준이며, 식약처의 공식 수치나 개인별 섭취 권장량으로 표시하지 않는다.**

## 확인한 공식 자료

1. 식품의약품안전처 [「식품등의 표시기준」 고시 전문, 제2026-37호(2026.5.12.)](https://www.mfds.go.kr/brd/m_211/view.do?seq=14968)의 **[표 3] 1회섭취참고량**. 공식 첨부 HWPX를 직접 읽어 아래 행을 확인했다. 영양표시에 사용하는 참고량이며 모든 사람에게 맞는 한 끼 식사량이나 요리별 원재료 투입량과 동일하게 취급하지 않는다. 실제 범위 확장 전 해당 시점의 개정·시행 내용을 다시 확인해야 한다.
2. 식약처 [식품영양성분DB정보 Open API](https://www.data.go.kr/data/15127578/openapi.do). [공식 카탈로그 메타데이터](https://www.data.go.kr/catalog/15127578/openapi.json)에 식품명·분류·코드·영양성분 함량 기준량·1회섭취 참고량·식품중량·출처·데이터 기준일 등이 명시되어 있다. 공개 메타데이터는 무료, JSON/XML, 이용허락범위 제한 없음으로 표시한다. 상세 페이지는 현재 조사 도구에서 표시 형식 오류가 나 공식 메타데이터와 제공기관 안내로 확인했다. 활용 승인·키 발급·실제 API 호출은 하지 않았다.
3. 식약처 K-FIND의 [공공데이터/Open API 안내](https://various.foodsafetykorea.go.kr/nutrient/industry/openApi/info.do). 가공식품·음식·원재료성 식품 표준데이터와 농촌진흥청 국가표준식품성분표 등 공식 연계 자료를 구분해 안내한다. 따라서 다른 식품군으로 확대할 때도 공공 자료를 출발점으로 삼을 수 있다.

| 식품 유형 | 확인한 1회 섭취참고량 |
| --- | --- |
| 과·채주스 / 과·채음료 | 200mL |
| 탄산음료 | 200mL |
| 탄산수 | 300mL |
| 커피 | 240mL |
| 숙면 | 200g |
| 당면을 제외한 건면 | 100g |
| 즉석조리식품의 밥 | 210g |

위 표는 고시 일부를 확인한 예시다. 특히 **영양성분 함량 기준량(예: 100g), 포장 전체 중량, 1회 섭취참고량, 실제 조리량**은 서로 다른 값이다. 건면/숙면처럼 조리 상태에 따라 구분해야 하고, 기준이 ‘1식’인 식품도 있어 모든 식품을 일률적인 g/mL로 바꿀 수 없다.

## 이번에 구현한 앱 규칙

- 원인 표본: 냉동 피자와 크랜베리 주스 메뉴에서 1인분 주스 사용량 1L를 제안했다. 이미 저장된 메뉴를 바꾸지 않고 **새 추천을 처리할 때** 보정한다.
- 해당 재료 이름이 주스·쥬스·과채음료·탄산음료·콜라·사이다·이온음료·스포츠음료로 끝나고, 별도 음식의 단독 주재료로서 `곁들이기`/`담아내기`에만 쓰이면 대상 후보로 삼는다. 공백은 무시한다. 브랜드명만 있거나 `주스 1L`처럼 끝부분이 다른 불명확한 이름은 추측하지 않는다.
- 농축/원액/베이스/시럽/분말/주류/특수용도 등 표시나 희석·혼합·조리 동작이 있으면 제외한다. 같은 재료를 다른 조리 음식에도 사용하면 합산량 중 마실 양을 알 수 없으므로 보정하지 않는다. 이 검사는 이름/구조/일부 표현 기반이며 식품 분류나 자유 문장의 의미를 완벽하게 판정하지 않는다.
- **재료별 250mL × 요청 인분을 초과한 양만 낮춘다.** 더 적은 제안을 올리지 않는다. 여러 음료가 있으면 음료별 기준이며 한 끼 전체 음료 합계나 영양 설계를 하는 기능은 아니다. 이 정책은 제품의 개/팩/병 용량을 추정하지 않으며 g→mL 변환도 하지 않는다. 양 또는 단위가 없으면 기존 확인 흐름을 유지한다.
- 알려진 `ml`/`L` 부피 단위만 계산하고, 보정할 때 표기 대소문자/공백을 정규화한다. 1인분 1L 제안은 0.25L, 2인분은 0.5L가 된다. 화면에 앱 기준과 보정량, 실제 사용량 수정 가능 안내를 표시한다.
- 같은 보정 결과를 재료 목록·저장 계획·차감 제안에 사용한다. 실제 재고가 부족하면 기존 부족 안내를 유지한다. 사용자가 차감 확인 화면에서 수정한 값은 다시 250mL로 강제하지 않는다. AI의 잘못된 참조/별도 수량 등 기존 일관성 실패를 보정으로 덮지 않는다.
- 외부 API·추가 Gemini 호출·새 키·마이그레이션·의존성은 없다. 이번 구현이 식약처 DB를 실시간 조회하거나 공공 기준 전부를 적용한 것은 아니다.

## 이후 확장 제안 — 미구현

공공 자료를 검토한 작은 기준표를 먼저 만들고 **식품 코드·분류·상태·단위·기준 종류·출처·자료 버전·확인일**을 함께 보관하는 방식을 권한다. 제품을 정확히 찾을 수 있으면 제품별 자료, 다음으로 식품 유형별 참고량, 마지막으로 합의한 앱 기본값을 검토한다. 모호한 경우에는 수량 확인을 요구한다. 어떤 공공 값을 앱 기본값으로 채택할지는 별도 결정 사항이다.

초기에는 검증한 표를 앱에 포함해 요청마다 외부 조회가 필요 없게 하고, 제품 DB 연동이 필요해지면 활용 신청 후 서버에서 캐시하며 갱신한다. 영양 기준을 모든 레시피의 조리량에 직접 적용하지 않는다. 사용자에게 250mL 앱 기준과 공식 주스 참고량 200mL의 차이를 알렸고, 이번 작업에서 임의로 200mL로 바꾸지 않았다.
