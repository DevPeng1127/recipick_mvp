# Recipick 기능 개발 우선순위와 첫 1시간 계획

작성일: 2026-10-26 (한국 시간)

이 문서는 기존 코드 점검 종료 이후의 제품 기능 개발 계획과 진행 기록이다. 사용자가 별도 브랜치에서 영수증 사진 자동 입력을 1시간 동안 구현·테스트하도록 승인했다. `phase2`의 `5ea0329`에서 분리한 **`codex/receipt-photo-import`** 브랜치에서 아래 영수증 초기 버전의 구현·검증을 완료하고, 사용자 컨펌 후 **`ad6b54e`로 로컬 커밋**했다. 다음 음성 입력은 앱에서 최대 60초 직접 녹음하는 방식으로 선택했다. 카카오 로그인 복구를 위해 중단한 뒤, 2026년 10월 28일 정상 로그인 확인과 재개 승인에 따라 **음성 초기 버전의 구현·검증을 완료했다. 사용자 결과 컨펌·커밋 승인에 따라 이번 로컬 커밋에 포함한다.** 가족 공유는 아래 제안의 범위·정책 확인 전까지 착수하지 않는다. 기존 점검 결과와 로그인 복구 기록은 [코드 점검 기록](code-audit-and-repair-log.md)에 보존한다.

## 사용자와 확정한 우선순위

| 순서 | 기능 | 목표 |
| --- | --- | --- |

| 1-2 | 음성 자동 입력 | 음성에서 식재료 후보 추출 → 사진 입력과 같은 확인·등록 흐름 재사용 |

사용자는 첫 1시간에 **영수증 사진 먼저**를 선택했다. 자동 입력의 사진·음성 작업을 우선하며, 한 항목 구현·검증 후 컨펌을 받고 다음으로 넘어가는 기존 방식을 유지한다. 시간 여유가 생겨도 가족 공유 등 다음 항목을 자동 시작하지 않는다.

## 모델과 사용량 결정

- 사용자는 **기존 Gemini Free 설정 유지, 영수증 인식과 레시피 추천을 기존 한도 안에서 합산**하는 안을 선택했다.
- 앱 자체 한도는 계정당 최근 60초 3회·하루 20회, 앱 전체 최근 60초 12회·하루 400회이다. 기존의 계정당 동시 AI 요청 1건도 함께 적용한다. 음성 입력 구현 후에는 **사진·음성·레시피 세 기능의 합산 한도**이다.
- 같은 프로젝트·모델에 대해 기능마다 전체 허용량을 복제하지 않는다. 실패한 실제 호출도 기존 집계 정책을 따른다. 한도 메시지는 두 기능에 맞게 조정한다.
- 기존 모델 `gemini-3.5-flash-lite`를 유지한다. 이미지 입력·구조화된 출력과 서버 응답 검증을 추가했으며 현재 계정의 실제 이미지 호출 성공을 확인했다. [모델 문서](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite)
- 유료 전환·새 공급자·모델 변경은 이 계획에 포함하지 않는다. 제공자에서 한도 오류가 오면 안내하고, 다른 유료 경로로 자동 전환하지 않는다.

## 첫 1시간 목표와 권장 범위

목표는 **보관함 화면에서 영수증 사진 한 장을 선택하고, 식재료 후보를 수정한 뒤 해당 보관함에 일괄 등록하는 초기 버전**이다. 로그인·보관함 권한·재고 모델·화면 구성·Gemini 연결·사용량 제어를 재사용했다. 아래 1~6은 이번 초기 버전에 구현했으며 검증 근거와 남은 한계는 하단에 기록했다.

1. **사진 선택:** JPEG/PNG 한 장, 원본 최대 5MB, 한 번에 최대 20개 식재료. 서버에서도 크기·실제 이미지 형식을 검사한다. 초과·손상 이미지는 인식 호출 전에 거절한다. HEIC/PDF·여러 장·내장 사진 편집은 후속 범위이다.
2. **후보 추출:** 원문 상품명과 정리한 식재료 이름, 구매 수량·단위 후보를 반환한다. 가격·합계·할인·비식품을 재고 후보에서 제외하도록 요청한다. 불명확한 값은 확인 필요로 표시하고, 품목을 확신할 수 없으면 사용자가 제외할 수 있어야 한다. AI 응답은 신뢰하지 않고 서버에서 구조·자료형·범위를 검증한다.
3. **확인 화면:** 원본 미리보기와 후보 목록을 보여준다. 이름·수량·단위·유통기한을 고치거나 후보를 제외할 수 있다. 수량·단위가 불명확하면 저장 전에 입력받는다. 유통기한은 기본적으로 비워 두며 구매일이나 임의의 날짜를 실제 유통기한으로 간주하지 않는다. `우유 1L × 2` 같은 표기는 구매 개수와 내용량을 구분하고 자동 단위 환산을 하지 않는다.
4. **명시적 저장:** 사용자가 확인 후 등록 버튼을 눌러야 DB에 저장한다. 첫 버전은 현재 보관함 하나에 새 재료 행으로 추가하며 기존 재고와 자동 합산하지 않는다. 여러 보관함에 나누는 기능은 후속 범위이다.
5. **일괄 등록:** 현재 단건 등록 로직을 활용하되 서버의 일괄 등록 API에서 권한과 전체 입력을 검사하고 하나의 트랜잭션으로 저장한다. 한 항목이라도 실패하면 전부 취소하여 일부만 등록되는 일을 막는다.
6. **실패와 재시도:** 인식 실패·빈 결과·한도 초과·저장 실패를 구분해 안내하고 수정 내용을 유지한다. 인식/저장 중 중복 클릭을 막고 자동 저장 재시도는 하지 않는다. 저장 응답이 끊긴 경우에는 목록 재조회로 반영 여부를 확인하도록 안내한다. 별도의 영수증 중복 판별이나 서버 재요청 멱등성 보장까지 완료됐다고 주장하지 않는다.

사진은 inline 방식으로 전달한다. 바이너리 본문을 최대 5MB까지 메모리에 읽으므로 multipart 임시 파일을 만들지 않는다. Pillow로 실제 형식·화소 수·손상 여부를 검사하고 카메라 방향을 적용한 뒤 EXIF·GPS 등 메타데이터 없이 JPEG로 재인코딩한다. 영수증 원본은 앱 서버 디스크·DB·로그에 남기지 않는다. 이 원칙은 앱의 보관 범위이며 Google의 처리·보관 정책까지 통제한다는 뜻은 아니다. [이미지 입력 문서](https://ai.google.dev/gemini-api/docs/image-understanding)

Free 서비스에서는 입력·출력이 제품 개선에 사용될 수 있고, Google은 개인정보·민감정보를 보내지 않도록 안내한다. 첫 실제 연결 검증은 **개인정보 없는 가상 영수증**으로 수행한다. 실제 사용 안내에는 결제·회원 정보 등을 제외한 상품 영역의 사진을 사용하도록 명시한다. 자동 개인정보 가림 기능은 첫 1시간에 포함하지 않는다. [Google 데이터 처리 조건](https://ai.google.dev/gemini-api/terms)

## 구현 시작 시점부터의 60분 배분

| 시간 | 작업 | 확인할 결과 |
| --- | --- | --- |
| 0~10분 | 입력·응답 형식과 실패 테스트 작성, 가상 영수증으로 모델 연결 확인 | 현재 키·모델로 이미지 인식 응답이 오는지, 추출 형식을 검증할 수 있는지 |
| 10~30분 | 인식 API·권한·합산 한도·응답 검증·일괄 등록 구현 | 확인 전 저장 없음, 허용된 보관함만 등록, 전부 성공 또는 전부 롤백 |
| 30~45분 | 보관함 화면의 사진 선택·결과 수정·등록 연결 | 사용자가 후보를 고치고 등록 결과를 확인하는 흐름 |
| 45~60분 | 핵심 회귀 테스트·브라우저 확인·린트/빌드·인계 기록 | 통과 결과와 실제 연결/대역 사용 구간, 미완료 부분을 구분한 보고 |

이는 작업량 추정이며 완료 시각을 보장하지 않는다. 기존 환경과 API가 정상인 경우 기본 흐름 하나를 끝내는 목표다. 이미지 품질 보정, 다양한 매장 양식 최적화, 전 기기 호환성과 정확도 평가까지 포함하는 시간은 아니다. 45분 이후에는 새 기능을 늘리지 않고 검증·정리에 집중한다. 외부 연결이나 핵심 검증이 막히면 완료 범위를 줄여 보고하고, 통과하지 않은 기능을 완료로 기록하지 않는다.

## 완료 판정

- 가상 영수증의 식품·비식품·가격 혼합 사례에서 후보 추출을 실제 Gemini 호출로 확인한다. 모의 응답 테스트 통과만으로 이미지 연결 성공을 선언하지 않는다.
- 인식 결과를 확인하는 동안 재고는 바뀌지 않고, 수정·제외 후 저장한 값이 DB에 반영된다.
- 유효하지 않은 수량·단위·이미지·AI 응답과 비회원 요청이 거절된다.
- 같은 앱 한도 안에서 영수증과 추천이 함께 집계되는지 기존 사용량 회귀 테스트로 확인한다.
- 격리된 PostgreSQL에서 일괄 저장 성공 및 도중 실패의 전체 롤백을 확인한다.
- 브라우저에서 선택 → 인식 → 수정/제외 → 등록 흐름과 실패 시 입력 보존을 확인한다. 실제 서비스 연결과 테스트 대역을 사용한 구간을 구분해서 기록한다.
- 기존 수동 등록·레시피 추천 회귀 테스트, 프런트 린트·빌드를 확인하고 변경 파일과 결과를 남긴다. 운영 배포는 하지 않는다.

## 후속 기능의 경계

- **음성 입력:** 앱에서 최대 60초 직접 녹음하고 후보 편집·등록 단계를 재사용하는 초기 버전을 완료했다. 기존 Gemini Free와 사진·레시피 합산 한도를 유지한다. 파일 업로드 UI는 첫 버전 범위가 아니다.
- **가족 공유:** 초대·수락·회원 관리와 역할별 권한을 구현한다. 초대 방식·유효기간·탈퇴/강퇴 정책은 해당 항목에서 결정한다.
- **스마트 차감:** 레시피에 재료 ID·수량·단위가 구조화되어 있어야 한다. 현재 텍스트 추천을 구조화하는 작업과 단위·남은 재고 검증을 이 단계에 포함한다. 자동 입력 단계에서 미리 확대하지 않는다.
- **마이페이지 대시보드:** 기존 소비·폐기 로그를 읽는 API와 기간/유형 필터, 처리 건수·최근 이력 UI를 만든다. 본인 이력과 공유 냉장고 이력 중 조회 범위는 해당 단계에서 정한다.
- **AI 보관 위치 추천:** 먼 미래의 후보로만 유지한다.

### 완료한 범위

- 보관함 화면의 **영수증으로 등록 → 사진 인식하기 → 후보 편집/제외 → 선택한 N개 등록** 흐름을 구현했다. 유통기한은 비워 두고, 확실하지 않은 수량·단위는 사용자가 입력해야 저장할 수 있다.
- 사진 1장, JPEG/PNG, 5MB·2천만 화소, 후보 최대 20개를 검사한다. 가격·합계·비식품 제외를 지시하고 AI 응답의 구조·이름·수량·단위·개수를 서버에서 다시 검증한다.
- 인식 단계에는 재고 쓰기가 없다. 명시적 등록 시 현재 보관함의 새 행으로 추가하며 전체 성공 또는 전체 롤백을 적용한다. 인식·등록 중 중복 클릭과 편집·닫기를 막는다.
- 권한, Gemini 설정, 레시피와 합산하는 영구 사용량 기록을 재사용한다. 신규 DB 마이그레이션이나 설정 키는 없다. `backend/pyproject.toml`에 `Pillow>=12.3.0,<13`을 추가했고 로컬 `.venv`에는 12.3.0을 설치했다.
- 저장 거절 시 입력을 보존한다. 네트워크 단절·5xx 등 결과가 불명확하면 재전송을 차단하고 닫기 후 재고 목록을 다시 조회하게 안내한다. 화면을 떠나면 진행 중 인식 요청을 취소하고 이미지 미리보기 URL을 해제한다.

### 실제 인식에서 발견한 문제와 수정

수정 후 데스크톱·모바일 녹음에서는 우유 2팩·계란 10개·사과 3개만 반환됐다. 별도 음성의 “양파 두 개, 아니 세 개”는 3개로 정정됐고, 수량·단위 없는 감자는 두 값을 null로 유지하며 확인 필요로 표시됐다. 같은 음성의 휴지와 폐기한 계란은 제외됐다. 이는 해당 합성 샘플의 결과이며 모든 발화의 정확도를 보장하지 않는다.

위 추천안은 아직 사용자 확정 사항이 아니다. 승인 후 공유 관리 화면, 링크 생성·수락·취소, 회원 목록·탈퇴·내보내기, 권한 검증과 두 계정 통합 테스트를 구현한다. 현재 코드에서는 회원도 냉장고 이름·보관함을 변경할 수 있으므로 추천 권한 정책이 승인되면 API와 화면을 함께 제한해야 한다. AI 한도는 계정별·앱 전체 기존 정책을 유지하며 별도 가족 한도를 추가하지 않는다.

현재 앱은 로컬 개발용이므로 첫 검증은 같은 PC의 별도 브라우저 세션·두 계정으로 진행한다. 가족의 다른 기기에서 쓰려면 접속 가능한 주소와 OAuth 설정을 별도로 준비해야 하며, 배포는 이 제안의 자동 승인 범위가 아니다.

## 인계 상태

- 현재 브랜치: **`codex/receipt-photo-import`**. 영수증 초기 버전은 **`ad6b54e` 커밋 완료**, 음성 변경·문서와 카카오 복구 기록은 사용자 승인에 따라 이번 커밋에 포함한다.
- 최신 사용자 지시: 2026년 10월 28일 음성 결과를 컨펌하고 커밋을 요청했다. 가족 공유의 구현 범위와 필요한 결정을 짧게 브리핑하도록 요청했으며 구현 승인은 아직 없다.
- `.env`와 기존 `.claude/`, `nul`은 변경하지 않으며 커밋 대상에 포함하지 않는다. 원격 푸시·배포는 하지 않았다.
- 사용자가 직접 확인할 순서: 백엔드 최신 코드 반영(자동 재로딩 또는 재시작) → 프런트 새로고침 → 냉장고의 보관함 → 음성으로 등록. [README](../README.md#음성으로-식재료-등록)의 녹음·확인·등록 흐름을 따른다. 음성 기능에 새 의존성이나 DB 마이그레이션은 없다.
- 다음 우선순위는 **가족 공유**이다. 위 미확정 추천안을 바탕으로 공유 단위·초대·권한·탈퇴 정책을 합의한 뒤 시작한다.
- 브라우저 도구 확인: 별도 Browser 플러그인은 현재 설치 검색에서 확인되지 않았지만 **내장 브라우저 제어 도구는 이미 사용 가능**하다. 10월 28일 현재 Recipick 대시보드의 URL·제목·화면 읽기로 연결을 확인했다. 앞선 별도 플러그인 설치 추천은 정정하며 기본 브라우저 제어에 추가 설치는 필요하지 않다. 음성 QA에서 사용한 Playwright/Chrome 검증 근거는 그대로 유효하다.
- 기존 점검 01~11은 종료 상태를 유지한다. 별도 운영용 JWT 키 준비는 배포 전에 다시 확인한다.
