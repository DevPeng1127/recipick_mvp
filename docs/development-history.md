# Recipick 개발 이력

정리일: 2026-11-02 (한국 시간). 개발 회고·진행 보고서·릴리스 노트를 만들 때 시작점으로 사용하는 요약이다. 현재 브랜치에 포함된 Git 기록과 기존 개발 문서를 근거로 작성했다. 초기 기록은 커밋 메시지 기준이며, 이번에 과거 기능을 다시 검증한 것은 아니다. 기능 구현·검증일과 커밋일이 다른 경우 별도로 적는다. 로컬 커밋 완료가 운영 배포 완료를 뜻하지 않는다.

## 문서별 역할

- 이 문서: 날짜순 주요 변경, 결정 이유, 검증 요약, 커밋을 연결하는 색인.
- [기능 개발 기록](feature-roadmap.md): 기능별 합의 사항, 구현 범위, 테스트 근거, 남은 제한.
- [코드 점검·인계 기록](code-audit-and-repair-log.md): 점검 01~11과 최신 작업 상태, 실패·재검증 및 데이터 보존 기록.
- [README](../README.md): 현재 기능 사용법과 개발 환경 실행 방법.
- [보관 기한 추천 기준](expiry-guidance.md): 추천 일수의 근거와 적용 조건.
- [배포 비용·API 사용량 검토](deployment-cost-plan.md): 1~10명 기준 무료 구성·신규 체험 비교, 코드상 AI 호출·한도와 배포 전 준비. 2026-10-30 조사, 11-02에 3개월 최소 비용 조건과 Cloud Run 우선안을 추가했으며 배포 구현·완료 기록은 아니다.

앞으로 완료한 작업은 한 항목씩 여기에 추가한다. **날짜 / 문제·목표 / 확정한 정책 / 완료 범위 / 검증 / 한계 / 커밋 또는 고유 이력 ID**를 남기고, 제안·보류·구현 완료·사용자 확인·커밋·배포 상태를 구분한다. 테스트 수는 해당 시점의 결과이며 서로 더해 누적 실행 수로 표시하지 않는다. 비밀키·실제 사용자 데이터는 기록하지 않는다.

## 메뉴 응답 일관성 개선 (2026-11-02)

- 목표: 메뉴 제목에는 달걀/볶음밥이 있지만 조리법·차감 재료에는 없는 실제 응답을 방지한다.
- 사용자 결정: 실제 주재료명 + 조리 방식 제목, 불일치 결과는 저장하지 않고 수동 재시도 안내. 자동 추가 AI 요청 없음.
- 구현: 구조화한 재료/음식/조리 단계의 참조를 검증하고 제목·표시용 본문·요구 재료를 같은 데이터에서 생성한다. 추가/누락/중복 참조, 별도 수량, 알려진 재료·공통 양념의 연결되지 않은 언급을 거절한다. 정확한 재고 이름을 보존하고 기존 저장 계획과 API/DB를 호환한다.
- 검증: 수정 전 실패 재현 후 백엔드 전체 **638개**, 프런트 **182개**, 린트·TypeScript/Vite 빌드 통과. 실제 격리 PostgreSQL/API의 저장/차감/복원/재시도·사용량 검증, 브라우저의 오류 안내·수동 재시도·복원·차감 미리보기 확인. 임시 서버/탭/스키마 정리 및 기존 DB 식별자 보존 완료. 상세 결과와 증빙은 [인계 기록](code-audit-and-repair-log.md)을 따른다.
- 실제 AI: 가상 재고 3회 중 마지막 응답의 기름 누락을 발견해 검증을 보강했다. 보강 후 저장된 응답 재검사에서 정상 2건 통과·누락 1건 거절. 추가 실제 AI 요청은 하지 않았다. 제목 일관성과 적정 인분·조리법 의미의 정확성을 구분하며 주스 1L 표본 등 양 제안의 한계는 남는다.
- 상태: `codex/menu-consistency`, 기준 `c256b5c`, **구현·검증·문서화·사용자 결과 컨펌 완료**. 사용자가 2026-11-02 커밋과 운영 반영을 승인하여 이번 로컬 커밋 후 재배포한다. 고유 이력 ID **`MENU-CONSISTENCY-20261102`**로 커밋을 찾는다. 배포 결과는 인계 기록의 후속 완료 기록을 따른다. 원격 푸시·다음 항목은 이번 범위 밖이다.

## 운영 배포 — 공개·기본 실사용 검증 완료, `c256b5c` 로컬 커밋 (2026-11-02)

- 최신 상태: 사용자 과금 조건·CLI 권한·Firebase 약관 승인 후 **Cloud Run API와 Firebase 정적 사이트 공개 완료**. 웹 `https://recipick-prod-1127.web.app`. 월 5,000원 프로젝트 전용 알림을 생성했으며 청구 상한은 아니다. 두 공급자의 실제 로그인과 카카오 시크릿 교체 후 재로그인, 사용자 첫 설정 이후 재고 저장·AI 추천·결과 복원·차감 미리보기·마이페이지 조회를 검증했다. 사용자 승인으로 테스트 재고 정리와 이번 로컬 커밋에 배포 코드·문서 반영까지 진행한다.
- 공개 검증: HTTPS health·미인증 거절·CORS·운영 콜백 URL·SPA 새로고침·캐시/빌드 주소 반영 확인. 운영 재고와 추정 날짜 저장·복원, 승인받은 Gemini 앱 요청 1회 성공·사용 기록 1건, 차감 계획 저장·미리보기, 마이페이지 빈 통계 정상. 반환된 브라우저 오류/경고 0건. 상세는 [배포 실행 문서](deployment-runbook.md).

- 목표/결정: 1~10명·약 3개월 최소 비용 운영을 위해 Firebase Hosting + Cloud Run + Neon Free + Gemini Free 선택. 현재 Google 계정과 빈 운영 DB를 사용한다.
- 완료 범위: 운영 API 주소/토큰 갱신, 검증 TLS와 연결 풀 복귀, 운영 설정 검사, 비루트 Linux 이미지·해시 고정 의존성·파일 허용 목록, Firebase SPA 설정. 개발 키와 다른 운영 JWT 생성·보호, Neon Free 프로젝트 생성.
- 검증: 백엔드 594개·프런트 181개, 린트·타입·정적 빌드·Linux 이미지 빌드 및 비밀 파일 제외 확인 통과. 기존 테스트 DB 식별자 보존. 실제 HTTPS 공개와 두 공급자 로그인 검증도 완료했다.
- 후속: CLI 인증과 새 운영 DB의 마이그레이션·TLS 1.3 확인 완료. 1GB/1CPU 컨테이너에서 최대 크기 합성 사진 두 장 동시 처리 통과(표본 최대 RSS 564.8MiB, AI 호출 없음).
- 상태: `codex/cloud-deployment`, 이번 로컬 커밋 반영·미푸시, Google Cloud/Firebase 공개 완료. 최초 과금 연결 자동 검토 거절 후 구체적인 월 5,000원 예산 알림 조건을 승인받아 진행했다. 카카오 개발자센터 상세 조회 중 로그인/비즈니스 인증 시크릿이 도구 출력에 포함되어 사용자에게 알리고 직접 재발급을 요청했다. 사용자 완료 확인 후 로그인 키를 출력 없이 개발·운영 설정에 반영했다. 현재 리비전 `recipick-api-00002-9nv`, 카카오 secret 버전 2, 이전 버전 사용 중지, 실제 재로그인과 HTTPS API 검사 통과다. 기존 Gemini 키/모델로 로컬 직접 요청 1회(입력 5/전체 6 토큰) 및 이후 운영 앱 요청 1회가 각각 성공했다. 커밋 제목 `chore: deploy Recipick to Cloud Run and Firebase`, 고유 이력 ID `DEPLOY-20261102`.
- 검증 범위·보존: 별도 테스트 냉장고·당근/양파만 사용했다. 실제 차감 확정 없이 재고 보존·소비/폐기 이력 0건을 확인했으며 사용자 승인 후 테스트 냉장고·보관함·재고를 삭제했다. 기존 냉장고 3개와 개인 설정은 보존하고 추천 계획/AI 사용 기록 1건은 유지했다. 운영 사진/마이크·가족 두 계정·차감 확정·모바일 실기기를 전부 다시 검증한 것은 아니다.
- 품질 한계: 실제 추천의 제목에는 달걀/볶음밥이 있으나 본문·재료 목록에는 없는 불일치가 관찰됐다. 별도 개선 후보이며 이번 배포에서 추가 수정하거나 AI를 재호출하지 않았다.
- 상세: [현재 인계 기록](code-audit-and-repair-log.md), [배포 실행·검증](deployment-runbook.md), [비용·사용량 근거](deployment-cost-plan.md). 공개 배포와 기본 실사용 검증은 완료했고 사용자 요청에 따라 현재 배포 항목을 로컬 커밋한다. 다음 추천은 메뉴 응답 일관성 개선이며, 구현 시작과 원격 푸시는 별도 확인 대기다.

### 최신 항목의 판단과 한계

- 문제: 냉동 피자를 도우로 취급하고 주스와 억지로 섞는 추천이 관찰됐다. 목표를 “새 레시피 만들기”에서 **보유 음식으로 현실적인 메뉴 구성하기**로 조정했다.
- 확정 정책: 선택한 재료를 우선 활용하되 별도 메뉴·곁들임으로 나누거나 제외 이유를 설명한다. 알레르기·제외 설정을 우선한다. 날짜 출처를 구분하고 날짜가 지난 항목은 우선 선택·자동 차감 배정에서 제외한다.

## Git 이력 조회·내보내기

저장소 루트에서 실행한다. 조회 대상은 **현재 브랜치 HEAD에 포함된 커밋**이며 다른 브랜치의 미병합 작업·미커밋 파일은 포함하지 않는다. 과거 커밋 메시지의 기술 스택은 당시 기록이며 현재 스택은 README를 따른다.

```powershell
# 최신 기능의 고유 ID로 커밋 조회
git log -1 --format="%h %s" --fixed-strings --grep="History-ID: MENU-20261030" HEAD

# 현재 브랜치에 포함된 변경을 오래된 순서로 조회
git log --reverse --date=iso-strict --format="%h %ad %s" HEAD

# Excel 등에서 사용할 CSV: 현재 사용자의 임시 폴더에 저장
git log --reverse --format="%H%x09%aI%x09%s" HEAD |
    ConvertFrom-Csv -Delimiter "`t" -Header commit, authored_at, title |
    Export-Csv -LiteralPath "$env:TEMP\recipick-git-history.csv" -NoTypeInformation -Encoding utf8
```

CSV는 커밋 원장이고 이 문서는 제품 변화의 요약이다. 보고서를 만들 때 두 자료와 상세 검증 문서를 함께 사용한다. 현재 브랜치 원격 푸시는 사용자 승인 후 완료했고, 기본 브랜치 병합·운영 배포는 별도 요청 대상이다. 배포 전 운영 전용 JWT 키 준비 확인 원칙을 유지한다.
